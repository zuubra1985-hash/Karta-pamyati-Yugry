# Даты, местоположения и полнота данных

В каждой карточке индексируется один год с типом события (`year` + `dateLabel`). Это может быть возникновение, строительство, перепись, список поселений, присвоение названия, упразднение или другое событие. Шкала и список карточек используют один и тот же отбор по типу события. Общая гистограмма не является распределением дат основания и не перечисляет все события жизни поселения. При выборе диапазона карточки с неизвестным годом исключаются; при выборе всех лет возвращаются.

## Исторические и современные объекты

`server/data/historical-contexts.json` содержит пояснения к Тром-Агану, Катесовым, устьевым юртам Агана и Боровому со ссылками на уже использованные источники. Пояснения добавляются в публичный ответ и отдельный статический экспорт без замены текстов, фото и оформления в рабочей базе.

У Тром-Агана отдельно показаны старое поселение из воспоминания о поездке 1956 года и современный посёлок 1971 года. Карточка индексируется по событию современного посёлка; приблизительная точка не используется для привязки старого. Воспоминание имеет отдельную подпись об историческом поселении. Пояснения не создают новых точек и не устанавливают неизвестные даты.

## Координаты

В исходных 36 паспортах 32 пары координат приблизительны, четыре отсутствуют: Пеньковы, Летний, Аган (устьевые юрты), Кедровый. Ни одна из них этой правкой не уточняется. Координаты без явной редакторской отметки `confirmed` отображаются как приблизительные. Карта показывает количества уточнённых, приблизительных и отсутствующих точек для текущего отбора. Неизвестные пары не заменяются географическим центром, одноимённым современным посёлком или случайной точкой.

Новый рассказ и его редакторскую правку можно отправить с неизвестным годом и обеими координатами `null`. Одна пустая координата при заполненной второй отклоняется сервером. Перевод в `confirmed` выполняет редактор после проверки основания; сама возможность выбрать статус не доказывает точность GPS.

## Незаполненные сведения

В карточках явно показаны отсутствующие воспоминания, неизвестное состояние, неподтверждённый охранный статус и отсутствие отдельной внешней публикации. Пустой статус не означает «не охраняется» или «разрушен». Для Летнего независимая публикация по-прежнему не установлена. В этой правке новые воспоминания, состояние и охранные статусы не выдумываются.

Кабинет имеет фильтры: без воспоминаний, без внешних публикаций, состояние не установлено, охранный статус не указан, GPS приблизительный, без координат, уточнить права на фото. Они формируют очередь проверки, а не автоматически подтверждают сведения.

## Фотографии

`photoCredit` и `afterPhotoCredit` хранят фотографа (`photographer`), дату съёмки (`date`), источник (`source`) и основание использования (`rights`). Эти поля проходят серверную проверку длины и структуры, сохраняются при модерации и в истории версий. Они являются заявленными сведениями, а не результатом юридической проверки разрешений.

Второй снимок использует существующие поля года и источника формы; они также записываются в его описание без повторного ввода. При замене основного изображения прежние права автоматически не переносятся; при удалении фото его описание очищается, предыдущая версия остаётся в закрытой истории. Неизвестные автор, дата или права показываются явно. Общие права проекта и источник исторического текста не считаются разрешением на чужой снимок.

Год исторического события не подставляется как дата съёмки. Год второго снимка не сравнивается с годом события: это независимые даты. Для первого снимка без даты сравнение показывает «дата съёмки не установлена».

## Резервное чтение

На Vercel используется `build:server`: статический исходный каталог не генерируется и не используется при отказе API. Сайт показывает ошибку и кнопку повторной загрузки. Это осознанный выбор сохранности актуальных публикаций: при отказе базы архив временно недоступен, зато старые фото и удалённые карточки не возвращаются из снимка Git.

Сборка `npm run build` вне Vercel по-прежнему позволяет создать отдельный статический сайт без базы. Он содержит данные из Git и не должен использоваться вместо актуальной рабочей базы. Резервное копирование Turso и соответствующих файлов Blob — отдельная процедура, описанная в VERCEL.md.

## Рассказы участников

Дополнение, отправленное из карточки, хранит неизменяемый при редакторской правке `relatedPlaceId`. При отправке сервер проверяет существование исходной опубликованной карточки. После одобрения рассказ появляется в общем каталоге, в разделе воспоминаний и среди историй участников у исходного места. Частный email не публикуется. Новые рассказы индексируются по событию «Воспоминание»; неизвестный год остаётся `null`. Фильтр «Без воспоминаний» учитывает и подготовленные свидетельства, и принятые связанные рассказы.
