# Полный архив на Vercel: Turso + закрытый Blob

Vercel размещает фронтенд и Node.js 24 Function `api/index.mjs`. Turso хранит карточки, материалы жителей, пароли (scrypt), сессии, журнал и общие ограничения запросов. Vercel Blob хранит фотографии. Локальный диск функции не используется. Без подключений API возвращает 503; публичный сайт может читать статический каталог сборки.

## Подключение проекта

В команде `sup-surgut` откройте **конкретный проект** сайта. Ссылка на команду не предоставляет доступ к управлению проектом из этой среды.

1. Создайте новую базу Turso, получите Database URL и auth token. Используйте отдельную базу для Preview, чтобы тестовые развёртывания не меняли рабочий архив.
2. В Vercel Storage создайте **Private Blob Store** и подключите к проекту. Нужен именно закрытый store: публичные ссылки обходили бы модерацию неопубликованных снимков.
3. В Settings → Environment Variables задайте серверные переменные:

| Имя | Значение |
|---|---|
| `TURSO_DATABASE_URL` | Сетевой адрес `libsql://…turso.io` |
| `TURSO_AUTH_TOKEN` | Токен базы, хранить как секрет |
| `BLOB_READ_WRITE_TOKEN` | Токен закрытого Blob Store (обычно добавляет интеграция) |
| `APP_ORIGIN` | Точный адрес production-сайта `https://…`, без завершающего `/` |

Токены не помещайте в `VITE_*`, Git или чат. Переменные нужны во время выполнения функции. Настройте Production и Preview раздельно; APP_ORIGIN должен совпадать с адресом, с которого выполняется вход, включая собственный домен. При доступе через другой alias изменения будут отклоняться проверкой origin.

4. Node.js: **24.x**; Build Command: `npm run build`; Output Directory: `dist`. Сохранённый `vercel.json` направляет `/api/*` в серверную функцию. Не заменяйте API общим rewrite на HTML.
5. После подключения переменных выполните новое развёртывание через Vercel. Изменение переменных само по себе не меняет уже запущенную версию.

Первое подключение создаёт таблицы и один раз импортирует 36 проверенных паспортов. Последующие холодные старты не заменяют правки и не восстанавливают удалённые карточки. Локальная рабочая база и её пользователи **не переносятся автоматически**. Если в ней уже есть реальные материалы, сохраните резервную копию и выполните отдельный перенос, прежде чем принимать новые материалы в облаке. Схема облачного `media` отличается: в ней закрытые ссылки Blob вместо SQLite BLOB. Не импортируйте локальный файл целиком поверх облачной схемы.

## Проверка и создание администратора

На доверенном компьютере с Node.js 24 и зависимостями проекта:

```bash
cp .env.example .env.cloud.local
```

Заполните локальный файл теми же значениями безопасным редактором. Файл исключён из Git. Не выводите его в логи. Затем:

```bash
npm run cloud:check
npm run admin:create:cloud
```

Первая команда проверяет Turso и загрузку/чтение/удаление небольшого закрытого тестового файла. Она также инициализирует таблицы и каталог при первом подключении. Вторая запрашивает email и дважды пароль в терминале. Пароль скрыт, открытой регистрации нет. Повторная команда с тем же email меняет пароль и отзывает сессии. Не создавайте редактора с тестовым паролем в production.

Откройте `/api/health`: ожидается `{"status":"ok"}`. Проверьте каталог, вход, изменение карточки, журнал, отправку материала и закрытость его фото до публикации. После повторного развёртывания правка и сессия должны сохраниться. Ссылки Blob не выдаются клиенту: `/api/media/:id` проверяет публикацию или сессию, затем читает закрытый файл.

## Ограничения и хранение

- Одна фотография — до 2 МБ. В Vercel запрос ограничен размером тела: приложение заранее отклоняет JSON более 4 МБ, поэтому два снимка вместе должны занимать примерно до 2,8 МБ. Уменьшите изображения, если форма просит об этом. Прямые загрузки большого размера пока не реализованы.
- Ограничения входа/отправки хранятся в Turso и действуют между экземплярами функций; окно — 15 минут. Нельзя заменять их памятью отдельной функции.
- SQL-правки и журнал выполняются в транзакциях; устаревшая версия отклоняется. Blob и SQL не имеют общей транзакции: при ошибке SQL сервер пытается удалить новую загрузку. Если удаление тоже не удалось, может остаться закрытый непривязанный файл. Не удаляйте старые снимки без проверки: их использует история версий.
- Лимиты и стоимость хранения зависят от тарифов Turso и Vercel. Платные ресурсы автоматически не создаются.
- Для восстановления нужны **оба** хранилища: резервная копия/экспорт базы Turso и соответствующие файлы Private Blob. Используйте штатные средства провайдеров и проверяйте восстановление. Локальная команда `npm run backup` копирует только локальную SQLite и не делает резервную копию облака.

## Что проверено в разработке

Тесты `tests/cloud-store.test.mjs` используют тот же libSQL-клиент с временной файловой базой и заменяют Blob тестовым хранилищем. Проверяются несколько экземпляров сервера, сохранение сессий, приватность фото, модерация, история, конфликт версий, общие лимиты и удаление новой загрузки после отката SQL. Это не подтверждает подключение реальных аккаунтов Turso/Blob. Для этого выполните `cloud:check` с действительными переменными и проверку развёрнутого сайта.
